# データベースマイグレーション ガイド

このガイドでは、kinpatsu-hiroin.comプロジェクトのデータベースマイグレーションの管理方法について説明します。DrizzleとCloudflare D1を使用したマイグレーション方法をカバーしています。

## 概要

当プロジェクトでは、以下の3つの環境に対応したデータベースマイグレーションシステムを採用しています：

- **ローカル開発環境** - ローカルテスト用のSQLiteデータベース
- **プレビュー環境** - Cloudflare D1のプレビューデータベース
- **本番環境** - Cloudflare D1の本番データベース

## コマンド一覧

| コマンド | 説明 |
|---------|-------------|
| `pnpm db:generate` | スキーマ変更に基づいてマイグレーションファイルを生成する |
| `pnpm db:push` | スキーマ変更を直接データベースにプッシュする（注意して使用すること） |
| `pnpm db:studio` | Drizzle Studioを開いてデータベースデータを閲覧・管理する |
| `pnpm db:local` | 最新のマイグレーションをローカルデータベースに適用する |
| `pnpm db:preview` | 最新のマイグレーションをプレビューデータベースに適用する |
| `pnpm db:prod` | 最新のマイグレーションを本番データベースに適用する |
| `pnpm db:all` | 最新のマイグレーションをすべての環境（ローカル、プレビュー、本番）に適用する |

## マイグレーションワークフロー

### 新しいマイグレーションの作成

データベーススキーマを変更する場合：

1. スキーマファイル（`src/database/schema.ts`）を更新する
2. マイグレーションファイルを生成する：
   ```bash
   pnpm db:generate
   ```
3. これにより、`drizzle/migrations`ディレクトリに新しいSQLマイグレーションファイルが作成される

### マイグレーションの適用

#### ローカル開発環境

ローカルテスト用にマイグレーションを適用：
```bash
pnpm db:local
```

#### プレビュー環境

Cloudflareのプレビュー環境でテストするために：
```bash
pnpm db:preview
```

#### 本番環境

本番データベースにマイグレーションを適用：
```bash
pnpm db:prod
```

#### すべての環境

すべての環境に一度にマイグレーションを適用：
```bash
pnpm db:all
```

### 高度な使用法

マイグレーションスクリプト（`scripts/migrate.ts`）は直接実行することでより柔軟な操作が可能です：

```bash
# 構文
tsx scripts/migrate.ts <environment> <mode> [--remote] [specificFile]

# 例
# 特定のマイグレーションをローカルに適用
tsx scripts/migrate.ts local specific 0001_some_migration.sql

# すべてのマイグレーションをプレビュー環境に適用
tsx scripts/migrate.ts preview all --remote

# 最新のマイグレーションを本番環境に適用
tsx scripts/migrate.ts production latest --remote
```

## トラブルシューティング

### よくある問題

1. **「テーブルが既に存在します」エラー**
   - マイグレーションスクリプトは `CREATE TABLE IF NOT EXISTS` を使用しているため、基本的には無視して問題ありません
   - テーブルを再作成する必要がある場合は、先に手動でテーブルを削除する必要があります

2. **スキーマ変更が反映されない**
   - スキーマファイルが正しく更新されていることを確認してください
   - `pnpm db:generate` を実行して新しいマイグレーションファイルを作成してください

3. **環境接続の問題**
   - Wranglerが正しく設定されていることを確認してください
   - Cloudflareの認証情報を確認してください
   - `wrangler.json`のデータベースバインディングを確認してください

### マイグレーションステータスの確認

適用されたマイグレーションを確認するには、Drizzle Studioを使用します：
```bash
pnpm db:studio
```

## マイグレーションアーキテクチャ

このシステムは以下のコンポーネントを使用しています：
- **Drizzle ORM** - スキーマ定義とマイグレーション生成
- **Cloudflare D1** - データベースプロバイダー
- **カスタムマイグレーションスクリプト** - 柔軟な環境ベースのマイグレーション

マイグレーションスクリプト（`scripts/migrate.ts`）は以下の処理を行います：
- 適用すべき適切なマイグレーションファイルの検索
- 冪等性を確保するための `IF NOT EXISTS` の追加
- ローカルまたはリモートデータベースの適切なターゲット設定
- 残りのマイグレーションを続行するためのエラー回復

## ベストプラクティス

1. 常にローカルで先にマイグレーションを生成してテストする
2. 本番環境の前にプレビュー環境にマイグレーションを適用する
3. マイグレーションを小さく焦点を絞ったものにする
4. 既に適用されたマイグレーションファイルを変更しない
5. `db:push` はデータ損失につながる可能性があるため、注意して使用する

## 一般的なワークフロー例

### 新機能開発時のDB変更

1. スキーマを変更：`src/database/schema.ts`を編集
2. マイグレーションを生成：`pnpm db:generate`
3. ローカルで適用：`pnpm db:local`
4. 動作確認後、プレビュー環境に適用：`pnpm db:preview`
5. 本番デプロイ前に、本番環境へ適用：`pnpm db:prod`
